# Polish 功能确认原型

这是可丢弃的交互确认版本，不是正式 CLI 改造。固定使用用户指定的简约飞书风格，不提供多套样式。

正式研发与验收依据见 [Polish 正式开发书](../../docs/polish-development-spec.md)。原型仍有整体提交错误关联元素、4 秒状态检查、缺少空闲会话自动唤醒和正式结束控件等缺口，不代表最终行为。

运行（需要本机已有 `lavish-axi` 和 Node 22+）：

```sh
prototypes/polish/polish serve
```

打开 <http://127.0.0.1:49792>。HTML 位于本目录的 `index.html`。实际反馈队列复用本机安装的 lavish-axi，使用独立端口和 `.lavish/polish-prototype` 状态目录，不修改其他 Lavish 会话。

当前 coding agent 在本会话执行：

```sh
prototypes/polish/polish poll
prototypes/polish/polish reply <comment-id> "回复正文"
```

`poll` 输出中的 `uid` 是 comment-id。回复只回到对应圆球，不由脚本模拟。长轮询需在当前 agent 活跃回合保持运行；本原型没有实现聊天结束后的 Codex 自动唤醒，也不另起模型会话。

## 当前范围

- 正文文字选区（包括标题、未标记文字和跨段选择）、内容块点击、鼠标附近浮窗。
- 浮窗无需 `@Codex`；默认与当前 session 的 agent 对话。
- 成功提交收球；`delivered_at` 确认 agent 接收后变橙色；对应评论的真实回复到达后恢复蓝色并显示新回复标记。
- 手动刷新加载回复和 HTML；用户勾选完成后移除对应圆球。
- 单选、多选、输入框和页面内提交独立可用，改变选项不会发送；点击提交才发给当前会话。
- 草稿、完成状态、表单答案保存在本浏览器 localStorage；正式版本需整合上游会话状态，原型不承诺跨浏览器恢复。
- 保留上游页面内交互能力是正式改造的约束，侧边栏会话区才是被替换的对象。本原型的表单用于验证交互，不替换上游 SDK。

## 已验证

2026-10-30，在真实浏览器及当前 Codex 会话完成：

- 内容块提交 → 当前会话 poll 收到 → reply 写入 → 刷新读取 → 用户完成 → 刷新不复活。
- 用户本人在页面提交“对，就是这样”和“测试，回复收到”，已按评论分别回复。
- `selection.browser.js` 修复前对章节标题失败，修复后通过标题、跨段选择、区外释放和表单不误触评论检查。
- 真实投递回执前为等待，agent 取走后橙色，真实回复后退出橙色且提示刷新。
- 草稿刷新保留、独立评论不串回复、窄屏浮窗避让、控制台无错误。

待用户继续体验后，吸收确认的交互并删除/整合原型；正式版再完成 CLI 命名和 Pi agent 端到端验证。
