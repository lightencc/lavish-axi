# Polish Pi 可用版本验证记录

日期：2026-10-31（Asia/Shanghai）。范围：本地 fork 的 Pi 版本；Codex 后置。代码未提交、推送或发布。全量验收与可用功能分别记录，不将单元测试替代真实 Pi 结果。

## 已实现并验证的用户流程

| 流程               | 证据与结论                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文字／内容块评论   | 真实浏览器打开定位浮窗，带选区引用；跨段 Range + mouseup 回归可打开完整两段引用。原生 drag 工具本次落到内容块，不能把它当作精确跨段鼠标选择的独立证明。                               |
| 两轮真实修订       | 同一 Pi 会话 `01a18dbc-b37e-756d-885d-c29bcef84c2e`：第一轮标题改为“同一 Pi 会话 · 第一轮已修订”；第二轮全局意见修改 intro。都由实际 Pi 工具改写文件并返回对应回复。                  |
| 手动刷新、完成     | 文件保存后旧页面保留；手动刷新后看到新 HTML 和回复。两轮均明确勾选完成；定位圆球消失，全局意见未产生圆球。                                                                            |
| 整体提交不关联元素 | UI、SDK 和 Store 回归覆盖无 selector/quote/tag/target 的普通全局提交，真实第二轮全局提交及原生表单均 `scope=session`，无元素小球。诊断批次保留 warning ID 业务数据，不伪造 DOM 锚点。 |
| 原生表单           | 单选和输入操作不弹评论、不发送；点击提交收到 Pi 的“表单已收到”。新测试页带 `data-lavish-question` 时，刷新恢复答案且不触发提交。                                                      |
| 结束通信           | 第一窗口整体确认 + 最终消息 + marker 均实际消费后 ended。最终构建窗口验证保留草稿结束，草稿不进入账本；显式 reopen 到 epoch 2 后恢复，再发送并结束，Pi 回复“最终意见已收到”。         |
| 恢复同一会话       | 性能窗口平稳关闭后，以同一 session 文件加载最终构建：绑定 instance/session 不变，generation 递增，原 30 条消息仍全部 replied，没有重新投递。不是中途崩溃测试。                        |
| 正式命令           | `pnpm run build` 生成可直接执行的 `dist/polish`；help/design 不启动宿主，无 Pi 绑定时拒绝静默创建替代 agent。                                                                         |

状态与运行材料在 [verification/polish-product](../verification/polish-product/)：`two-rounds-and-end.json`、`resumed-and-ended.json`、各窗口 `events.jsonl`、Pi session 文件与 HTML。浏览器截图通过工具内联检查；截图文件保存被工具路径权限拒绝，未修改权限，因此本目录不声称存在截图文件。

## 响应采样

模型：`magpie / grok/grok-4.7`，thinking `medium`；Pi 1.4.0。本机 loopback 服务。Pi session 为 `01a18dc9-6e05-777c-aa20-3918f71a8078`。

网页 30 次由实际 UI 发送“性能验证 N：不要修改文件、不要使用工具，只回复 OK。”，真实 Pi 逐条回复 OK；随后同一会话经直接 Pi 输入再做 30 次同样请求。均无失败或未完成；这不包含下面单独记录的早期脚本失败窗口。

| 指标（毫秒）                      | N   | P50    | P95    | 最大值 |
| --------------------------------- | --- | ------ | ------ | ------ |
| 点击发送 → 按钮禁用反馈           | 30  | 1.2    | 1.7    | 2.6    |
| 点击发送 → HTTP 接收回执          | 30  | 15.3   | 19.7   | 41.0   |
| 点击发送 → 橙色处理提示           | 30  | 85.3   | 97.2   | 103.8  |
| 点击发送 → 浏览器收到真实消费状态 | 30  | 87.7   | 98.7   | 103.9  |
| 点击发送 → 浏览器收到对应最终回复 | 30  | 1385.4 | 2290.4 | 7467.3 |
| 直接 Pi 输入 → agent settled      | 30  | 1283   | 1763   | 2881   |

原始样本：[browser-30.json](../verification/polish-product/evidence/browser-30.json)、[direct-30.json](../verification/polish-product/evidence/direct-30.json)；汇总：[performance-summary.json](../verification/polish-product/evidence/performance-summary.json)。nearest-rank 计算 P50/P95，未删除慢样本。

浏览器各起止点使用同一 `performance.now()` 时钟；直接输入各起止点使用测试进程同一时钟，不跨时钟相减。网页 30 次先于直接 30 次，历史长度随会话增长，两个终点也不同；这是方向性对照，不能将分位数相减宣称精确的 Polish 额外开销。接收、排队、消费、回复分开保存为状态，但本次没有分别测出服务端落库→宿主入队、模型首 token、回复落库→UI 绘制的全部源头延迟；G07 的完整分阶段门槛未全验。

## 回归与失败记录

- 新回归先红后绿：全局不带锚点、丢失唤醒、跨 Pi 会话拒绝投递、精确回复关联、完成与追问竞态、实际 HTML 字节检查、固定结束请求重试、草稿恢复、明确拒绝可修改重试、未知发送不盲重发、结束后停止文件监听与广播、reopen 后迟到回复只归档、已发送最终草稿不复活。
- build / lint / format / typecheck / skill 与 plugin 新鲜度检查通过。全量 `pnpm run check` 的最终计数见下方交付检查结果；唯一已定位环境失败为 `test/server-discovery.test.js` 的不可解析域名案例。本机实际将 `lavish-unresolvable.invalid` 解析成 `198.18.0.82`，与测试前提不同。未跳过该测试、未修改 DNS、安全设置或放宽断言。
- 第一个产品测试窗口 `163b08a0-ffe9-4821-9046-1d385666436e` 因测试 logger 将 Pi 的字符串消息当数组而中断，1 条尝试留为未完成，未重放。修正测试 logger 后启动新的普通测试窗口。该失败及日志仍保留，不算成成功往返。
- 原 M0 的 600 秒受控窗口已按原限制结束；历史证据和报告保留原字节，由 `.prettierignore` 排除格式改写。它们不是当前源码 hash 的证明。

## 实际限制

- 正式产品的中途崩溃、断网重连、忙碌并发矩阵尚未全部用真实 Pi 重跑；Store/HTTP 回归及历史 M0 不能冒充这些项通过。
- 精确跨段鼠标拖选、鼠标在 iframe 外释放及窄屏/键盘完整矩阵仍需补充原生输入验证。已验证共享选区处理器，不声称完整浏览器矩阵。
- 未发送草稿存于原浏览器的当前服务 origin。服务重启换端口、换浏览器时不会自动迁移；服务端已接受的消息和完成历史会恢复。
- 浏览器可能阻止关闭手动打开的页；此时明确显示“通信已结束 · 可以关闭此页”。本次由 DevTools 创建的页没有自动关闭，不能声称所有浏览器自动关页通过。
- 原队列/附件/白板/布局能力保留代码路径和既有回归；本次真实 Pi 重点验证表单，并未重新执行所有旧功能的浏览器矩阵。
