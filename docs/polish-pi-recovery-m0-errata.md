# Pi M0 恢复报告语义勘误

日期：2026-10-30。对应恢复机制 r1.1 和产品开发书 v1.2。原报告、原始事件及 manifest 保持原样；本文件修正结论口径，不改变实验事实。

1. **投递未知与回复关联未知分开。** `delivery_unknown` 表示无法证明输入是否被消费，适用 §7.5／G04：不得盲目重投，不能宣称恢复门槛通过。`delivered + executionUnknown` 表示已有真实输入消费证据，但不能核实对应回复，适用 §8.1：不得按正文或邻接记录猜测归属。后者本身不是 G04 投递恢复失败的证据。
2. **r1.1 的 reply-before-receipt 实验属于后者。** 消息 `r1-a81fc59b-b833-44c0-8755-659a97874379` 已有 `context_with_system` 输入证明，缺少回复关联 receipt。原报告 §4 的恢复边界描述及 §5 G04 行把这一缺口归入完整投递恢复失败，范围过宽。正确结论是回复关联仍未知、禁止重投；G04 的真实投递未知窗口需要独立实验，不能由此代替。已有 receipt 窗口的正向恢复结果依然成立。
3. **结束门槛是消费，不是回答。** 按 §6.2，固定最终批次和结束标记都进入绑定 session 的真实处理输入后即可 `ended`，无需等待模型回答、回复 receipt 或 HTML 文件修改。已经确认消费的消息缺少回复关联，不应仅因此阻止结束。未证实消费的消息仍阻止结束。
4. **不扩张验收。** v1.2 不因这次勘误增加任意工具副作用恢复、完整 exactly-once 或额外高可用要求。当前阶段验证消息身份、当前活动实例、真实消费、正向查询、唯一消费权和固定结束集合。完整 Pi M0 仍需对应的组合及网页证据，不能由这次文字修正直接放行。
